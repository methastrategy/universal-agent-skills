# Merea

เริ่มจากผลที่ยืนยันได้ ไล่ย้อนหากลไกและเงื่อนไข แล้วสังเคราะห์ว่าส่วนไหนนำไปใช้ที่อื่นได้

## เลือกเส้นทาง

- **แนวคิด โพสต์ และระบบงาน** ใช้ [แนวทางแกะระบบ](references/conceptual-reverse-engineering.md) หา input, กลไก, output, แรงจูงใจหรือ feedback loop ที่มีหลักฐาน และข้อจำกัดในการย้ายแนวคิดข้ามบริบท
- **โค้ดหรือไฟล์ซอฟต์แวร์ที่ได้รับอนุญาตให้ตรวจ** ระบุชนิดไฟล์และ packaging จากตัว artifact ก่อน อ่านซอร์ส เอกสาร หรือ metadata ที่ตรวจได้ หากต้องใช้ REA ให้ตรวจว่าเครื่องมือและ provider ที่ติดตั้งรองรับเป้าหมายนั้น จึงอ่าน [คู่มือ REA](references/rea-technical-guide.md) ใช้เวอร์ชันที่เข้ากันกับงาน ระบุความสามารถที่ขาดและหลักฐานที่ยังมี หากเครื่องมือไม่รองรับให้จบที่ข้อสรุปที่พิสูจน์ได้จากหลักฐานอื่น
- **รายงานหรือประวัติ EA** ใช้ [แนวทางอ่านหลักฐานกลยุทธ์](references/ea-strategy-reverse-engineering.md) เพื่อแยกพฤติกรรมที่สังเกตจากสมมติฐาน ส่งการคอมไพล์ ทดสอบซ้ำ และจูนไปที่ `mql5-ea`

## วิธีสังเคราะห์

1. ระบุผลที่สังเกตจริง แหล่งที่มา เวอร์ชัน และสิ่งที่ข้อมูลยังไม่ตอบ
2. ไล่ย้อนจากผลไปหาเหตุ โดยจับให้ได้ว่าแต่ละขั้นต้องอาศัยอะไรและมีหลักฐานตรงไหน
3. เปรียบเทียบสมมติฐานที่อธิบายผลได้ ระบุหลักฐานที่แยกสมมติฐานได้จริง เช่น branch ของโค้ด สถานะก่อนและหลัง ค่าใน registry หรือผลทดสอบซ้ำ
4. สกัดหลักการที่พกไปใช้ได้ ระบุข้อแลกเปลี่ยน จุดที่ไม่เหมาะจะย้าย และเกณฑ์ตรวจตอนนำไปใช้ หากถูกเรียกจาก `optimize` ให้คืนข้อมูลนี้เพื่อเทียบกับระบบของผู้ใช้

ใช้ [โครงรายงาน](references/report-template.md) กับงานที่ซับซ้อน ใส่แผนภาพเมื่อลำดับเหตุหรือความสัมพันธ์หลายทางอ่านยาก ให้แยกผลตรวจ การอนุมาน และเรื่องที่ยังพิสูจน์ไม่ได้ด้วยภาษาตรงไปตรงมา
