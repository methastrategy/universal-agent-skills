# /summarize — High-Density Factual Summarization

Condense massive documents, complex specification files, or lengthy code blocks into crystal-clear, high-density factual matrices with zero fluff, backed by the **Dual-Partition Confession Box Protocol**.

---

## 1. ลูปการทำงาน (Operational Steps)

1. **Extract Critical Parameters**: สแกนหาตัวเลข ตัวแปร ข้อกำหนดทางวิศวกรรม และการตัดสินใจที่ระบุไว้ชัดเจน
2. **Discard Informational Fluff**: ตัดคำเชื่อม บทนำ การอารัมภบท และข้อความเสริมที่ไม่ใช่สาระสำคัญทิ้ง 100%
3. **Partition Verification (กล่องสารภาพ)**: แยกสิ่งที่ยืนยันได้ตรงตัว ออกจากสมมติฐานหรือการอนุมานอย่างเด็ดขาด
4. **Synthesize Fact Matrix**: บีบอัดเนื้อหาลงในตารางหรือ Bullet Block ความหนาแน่นสูง
5. **Compression Telemetry**: คำนวณอัตราส่วนการบีบอัดข้อมูล (Compression Ratio) เปรียบเทียบก่อน-หลัง

---

## 2. กฎเหล็กแบ่ง 2 กล่องสยบมโน (Dual-Partition Confession Box Invariant)

เมื่อสรุปเอกสาร คู่มือหนาๆ สัญญา สเปกงาน หรือเปเปอร์วิจัย ให้แบ่งโครงสร้างผลลัพธ์เป็น 2 ส่วนแยกขาดจากกันเสมอ:

```markdown
### 📌 [สิ่งที่ยืนยันได้จริงจากเอกสาร]
- ดึงเฉพาะข้อความ ตัวเลข หรือข้อกำหนดที่มีหลักฐานระบุไว้ชัดเจนในไฟล์เท่านั้น
- ห้ามเดาหรือตีความเสริม หากเอกสารไม่ได้ระบุไว้ ให้ตอบตรงๆ ทันทีว่า "ในเอกสารไม่ได้ระบุไว้"

### 🧪 [กล่องสารภาพ & สมมติฐานต่อยอด] (The Confession Box)
- หากจำเป็นต้องให้ความเห็นเชิงวิศวกรรม ข้อเสนอแนะเพิ่มเติม หรือการอนุมานจากประสบการณ์ ให้รวบมาไว้ในกล่องนี้ทั้งหมด
- ทำหน้าที่เป็น Escape Hatch ระบายสมมติฐานของโมเดล ป้องกันไม่ให้การคาดเดาปะปนกับข้อเท็จจริงในเอกสารอย่างเด็ดขาด
```

---

## 3. Checklist การตรวจรับงาน

- **Executive Core**: สรุปแก่นสาระของเอกสารใน 1–2 บรรทัดแรก
- **Zero Editorializing in Partition 1**: ห้ามใส่ความเห็นส่วนตัวในกล่องข้อเท็จจริงเด็ดขาด
- **Exact Numeric Constants**: คงค่าตัวเลข ค่าคงที่ และชื่อฟิลด์ให้ตรงตามต้นฉบับทุกตัวอักษร
- **Compression Ratio**: ระบุสัดส่วนการลดรูปของเนื้อหา (เช่น บีบอัดจาก 5,000 คำเหลือ 250 คำ = 95% Compression)
